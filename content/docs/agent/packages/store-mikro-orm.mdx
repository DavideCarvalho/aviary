The `AgentStore` SPI (from `@dudousxd/nestjs-agent-core`) backed by MikroORM. The store is a POJO
that receives an `EntityManager`; every operation runs on a fresh `em.fork()` so per-request
identity maps never bleed across concurrent turns.

## Minimal example

```ts
import { MikroOrmModule } from '@mikro-orm/nestjs';
import { MikroOrmAgentStoreModule } from '@dudousxd/nestjs-agent-store-mikro-orm';
import { AgentModule } from '@dudousxd/nestjs-agent';

@Module({
  imports: [
    MikroOrmModule.forRoot(/* your config */),
    MikroOrmAgentStoreModule.forFeature(), // registers entities + binds AGENT_STORE (+ queries)
    AgentModule.forRoot({
      model: myModelProvider,
      // no `store` — the agent reads it from AGENT_STORE
      defaultRoles: ['ADMIN'],
      actorResolver: new HeaderActorResolver(),
    }),
  ],
})
export class AppModule {}
```

Create the tables with your normal MikroORM migrations, or call the exported `ensureAgentSchema`
helper at boot for a quick start:

```ts
import { ensureAgentSchema } from '@dudousxd/nestjs-agent-store-mikro-orm';

await ensureAgentSchema(orm); // orm.schema.update({ safe: true }) — create + add-column only
```

<Callout type="warn" title="MikroOrmAgentStoreModule.forFeature() is global">
It binds `AGENT_STORE`, `AGENT_GOVERNANCE_QUERIES`, and `AGENT_PRICING_STORE` on a **global** Nest
module. Import it once —
`AgentModule.forRoot({...})` (and the dashboard/telescope surfaces) resolve both tokens app-wide with
no re-binding. Do not import it more than once expecting scoped behavior.
</Callout>

## Exports

| Export | Kind | Purpose |
|---|---|---|
| `MikroOrmAgentStoreModule` | `DynamicModule` factory | `.forFeature()` registers the agent entities and binds `AGENT_STORE` + `AGENT_GOVERNANCE_QUERIES` + `AGENT_PRICING_STORE` globally |
| `MikroOrmAgentStore` | class | `AgentStore` implementation — the write side (threads, messages, tool calls, usage), including `updateThread` (title and/or the thread's `defaultAgent`), the projected `defaultAgentForThread` and `loadThreadForTurn` reads (see [what a turn reads off a thread](/docs/agent/guides/persistence#what-a-turn-reads-off-a-thread)), `referencedMediaIds` (which media a live message still carries — the library half of [attachment collection](/docs/agent/guides/persistence#which-media-a-message-still-references-optional)), and the optional `recordRunStart`/`recordRunEnd`/`bumpRunRetries` run-reliability hooks the loop and durable runners call |
| `MikroOrmMemoryProvider` | class | `MemoryProvider` implementation over `agent_memory` — `list` (scope-gated in the query), `write` (upsert on the (`scope`, `key`) unique index, with `pinned`/`created_at`/`id` out of the conflict merge), `forget` (the actor's own scope in the `where`), plus `pin({ id, pinned })` for the console. No `search` — see [Memory](/docs/agent/guides/memory#search-on-the-provider) |
| `MikroOrmGovernanceQueries` | class | `AgentGovernanceQueries` implementation — the full read-model: spend by model/actor/thread, usage trend, recent activity, run reliability (`runMetrics`/`runsByAgent`/`runErrors`/`runTrend`/`recentRuns`), the approvals inbox (`pendingApprovals`), per-tool stats (`toolStats`), and paged/filterable reads (`toolCallsPage`/`threadsPage`/`runsPage`) |
| `MikroOrmPricingStore` | class | `AgentPricingStore` implementation — `upsertModelPrice` / `listCurrentPrices`, the write side of model pricing (see [Cost & Governance](/docs/agent/guides/cost-and-governance#seeding-prices)) |
| `ensureAgentSchema(orm, opts?)` | function | Non-destructive `schema.update({ safe: true })` — create + add-column, never drop or alter. Re-diffs afterwards and throws `AgentSchemaHealError` rather than record a heal that did not apply |
| `AgentSchemaHealError` | class | Thrown when structure the diff asked for is still pending after the heal; carries the pending statements. The schema fingerprint is NOT recorded, so the next boot retries |
| `agentManagedTables()` | function → `string[]` | Every table this store owns, for a host's own MikroORM schema-diff `skipTables` — mirrors `durableManagedTables()`/`telescopeManagedTables()` |
| `AGENT_ENTITIES` | `EntitySchema[]` | The agent entity schemas, pre-stamped with `utf8mb4_unicode_ci` for MySQL parity |
| `agentEntities({ collation? })` | function | Builds the entity schemas with a custom (or no) collation, e.g. for SQLite |
| `AGENT_COLLATION` | `'utf8mb4_unicode_ci'` | The default collation baked into `AGENT_ENTITIES` |
| entity classes (`AgentThread`, `AgentMessage`, `AgentToolCall`, `AgentTokenUsage`, `AgentModelPricing`, `AgentRun`, `AgentMemory`, `RagIngestionLog`) | `EntitySchema`-backed classes | The tables this store owns — `agent_thread`, `agent_message`, `agent_tool_call`, `agent_token_usage`, `agent_model_pricing`, `agent_run`, `agent_memory`, `rag_ingestion_log` |

<Callout type="info" title="referencedMediaIds needs no migration">
`referencedMediaIds(actorRef, mediaIds)` — the library half of
[attachment collection](/docs/agent/guides/persistence#which-media-a-message-still-references-optional)
— reads the `attachments` JSON column `agent_message` has carried since attachments shipped, so an
existing database answers correctly the moment you upgrade. No new table, no column, no backfill,
and no boot-time heal in the path at all. The match
runs in memory rather than in SQL (the column holds an array of objects, no dialect indexes that),
bounded to one actor's attachment-bearing messages. A soft-deleted thread still counts as holding
its references: the rows survive, so the bytes are still reachable.
</Callout>

<Callout type="info" title="How the add-column heal works on SQLite">
The heal applies `getUpdateSchemaSQL({ safe: true })` and keeps the statements whose every named
table is an agent table. On MySQL and Postgres a new column is a plain `alter table … add column`. On
**SQLite/libsql** MikroORM expresses the same change as a table rebuild (`create table
agent_thread__temp_alter` → copy → `drop` → `rename`), which is kept as a unit and run with
foreign-key enforcement off, restored afterwards — dropping `agent_thread` with enforcement on fires
the children's `on delete cascade` and would take every message with it.

The heal then re-diffs and throws `AgentSchemaHealError` if required structure is still pending, and
the schema fingerprint is written only after it returns. A heal the database refused (no DDL grant, a
managed schema) therefore fails the boot with the pending statements in the message instead of being
recorded as applied — apply them with [`agentSchemaSql`](#exports) in a migration.
</Callout>

<Callout type="info" title="Why this list is one longer than Drizzle's">
This adapter also owns `rag_ingestion_log` — `@dudousxd/nestjs-agent-rag` writes its ingest
ledger through the same `EntityManager`, so this store creates and heals that table too even
though it carries no `agent_` prefix. `store-drizzle` has no counterpart: its `agentSchema` is
the agent tables alone, and a Drizzle deployment using RAG owns that table itself.
</Callout>

<Callout type="info" title="agent_memory — the library owns this one, and not a skill table">
[Memory](/docs/agent/guides/memory) rows live in `agent_memory`, created and healed like the rest.
That looks inconsistent next to skills, whose rows are always the host's, and the difference is what
a row can be related to: a skill plausibly joins your own entities (who authored it, which sector,
which review approved it), while a memory is a key, a fact, an **opaque** scope token and an origin.
Every other part of memory was already the library's — the `remember` tool, `writeMemory`, the
`memory:digest` checkpoint, and the read-back and delete endpoints — so storage was the only half a
consumer had to invent.

`MikroOrmAgentStoreModule.forFeature()` exports `MikroOrmMemoryProvider` but never binds
`AGENT_MEMORY`: that token's presence is what turns memory on, so binding it would give the feature
to every host that installed the store.
</Callout>

<Callout type="info" title="agent_run — the reliability + approvals table">
Every turn is recorded as a run in `agent_run` (status, duration, error code/message, retry count, a
`promptHash` for correlating error-rate shifts with prompt changes, and `parent_run_id` — the run
that delegated this one, so a delegation's cost rolls up to the turn that asked for it even when the
child is detached and outlives that turn). `MikroOrmGovernanceQueries` reads
it for the dashboard's Reliability section and for `pendingApprovals`/`toolStats` — created and
healed by `ensureAgentSchema` like every other table here, no separate wiring needed.
</Callout>

## Peer dependencies

`@mikro-orm/core` (`^6 \|\| ^7`), `@mikro-orm/nestjs` (`^6 \|\| ^7`), and `@nestjs/common`
(`^10 \|\| ^11`) — plus your driver package (`@mikro-orm/postgresql`, `@mikro-orm/mysql`, …).

## When to use it

Reach for this adapter when MikroORM is already your app's ORM — `MikroOrmModule.forRoot(...)`
owns the connection, and `forFeature()` just registers the agent's entities alongside your own.
If you'd rather bring an already-opened handle and skip MikroORM entirely, see
[`store-drizzle`](/docs/agent/packages/store-drizzle).
