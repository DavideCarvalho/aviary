The `AgentStore` SPI (from `@dudousxd/nestjs-agent-core`) backed by Drizzle. Unlike the MikroORM
adapter, this package never opens a connection itself — the host app owns and hands it an
already-opened Drizzle db.

## Minimal example

Any SQLite-dialect driver works (better-sqlite3, libsql, D1, …):

```ts
import Database from 'better-sqlite3';
import { drizzle } from 'drizzle-orm/better-sqlite3';
import {
  DrizzleAgentStoreModule,
  agentSchema,
  ensureAgentSchema,
} from '@dudousxd/nestjs-agent-store-drizzle';
import { AgentModule } from '@dudousxd/nestjs-agent';

const db = drizzle(new Database('app.db'), { schema: agentSchema });
await ensureAgentSchema(db); // idempotent CREATE TABLE IF NOT EXISTS — or run your own migrations

@Module({
  imports: [
    DrizzleAgentStoreModule.forRoot({ db }), // binds AGENT_STORE + AGENT_GOVERNANCE_QUERIES
    AgentModule.forRoot({
      model: myModelProvider,
      defaultRoles: ['ADMIN'],
      actorResolver: new HeaderActorResolver(),
    }),
  ],
})
export class AppModule {}
```

<Callout type="warn" title="DrizzleAgentStoreModule.forRoot() is global">
Like the MikroORM adapter, this module binds `AGENT_STORE`, `AGENT_GOVERNANCE_QUERIES`, and
`AGENT_PRICING_STORE` on a **global** Nest module. Import it once — the agent, dashboard, and
telescope surfaces all resolve all three tokens app-wide with no re-binding.
</Callout>

<Callout type="info" title="ensureAgentSchema is a quick start, not a migration story">
It is additive only: `CREATE TABLE IF NOT EXISTS` plus `CREATE INDEX IF NOT EXISTS`, and an explicit
add-column pass for columns this package introduced after a table shipped — so an existing database
picks those up on the next boot rather than only a fresh one. It never drops a column and never
changes a type. Prefer drizzle-kit migrations in production; treat `ensureAgentSchema` as the "stand
it up with no migration files" path for tests, demos, and first boot. On your own migrations, the
additive statements are yours to write:

```sql
ALTER TABLE agent_thread ADD COLUMN default_agent TEXT;
ALTER TABLE agent_message ADD COLUMN run_id TEXT;
ALTER TABLE agent_message ADD COLUMN attachments TEXT;
ALTER TABLE agent_run ADD COLUMN parent_run_id TEXT;
CREATE INDEX agent_tool_call_message_idx ON agent_tool_call (message_id);
```
</Callout>

## Exports

| Export | Kind | Purpose |
|---|---|---|
| `DrizzleAgentStoreModule` | `DynamicModule` factory | `.forRoot({ db })` binds `AGENT_STORE` + `AGENT_GOVERNANCE_QUERIES` + `AGENT_PRICING_STORE` globally over your db handle |
| `DrizzleAgentStore` | class | `AgentStore` implementation — the write side, including `updateThread` (title and/or the thread's `defaultAgent`), the projected `defaultAgentForThread` and `loadThreadForTurn` reads (see [what a turn reads off a thread](/docs/agent/guides/persistence#what-a-turn-reads-off-a-thread)), `referencedMediaIds` (which media a live message still carries — the library half of [attachment collection](/docs/agent/guides/persistence#which-media-a-message-still-references-optional)), and the optional `recordRunStart`/`recordRunEnd`/`bumpRunRetries` run-reliability hooks the loop and durable runners call |
| `DrizzleMemoryProvider` | class | `MemoryProvider` implementation over `agent_memory` — `list` (scope-gated in the query), `write` (upsert on the (`scope`, `key`) unique index, whose conflict `set` names exactly what a rewrite may change, so `pinned`/`created_at`/`id` are left alone), `forget` (the actor's own scope in the `where`), plus `pin({ id, pinned })` for the console. No `search` — see [Memory](/docs/agent/guides/memory#search-on-the-provider) |
| `DrizzleGovernanceQueries` | class | `AgentGovernanceQueries` implementation — the full read-model: spend by model/actor/thread, usage trend, recent activity, run reliability (`runMetrics`/`runsByAgent`/`runErrors`/`runTrend`/`recentRuns`), the approvals inbox (`pendingApprovals`), per-tool stats (`toolStats`), and paged/filterable reads (`toolCallsPage`/`threadsPage`/`runsPage`) |
| `DrizzlePricingStore` | class | `AgentPricingStore` implementation — `upsertModelPrice` / `listCurrentPrices`, the write side of model pricing (see [Cost & Governance](/docs/agent/guides/cost-and-governance#seeding-prices)) |
| `agentSchema` | Drizzle schema object | The seven agent tables (`agentThread`, `agentMessage`, `agentToolCall`, `agentTokenUsage`, `agentModelPricing`, `agentRun`, `agentMemory`) |
| `ensureAgentSchema(db)` | function | Idempotent `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS` DDL for every table, plus an add-column pass for columns introduced after a table shipped |
| `AgentDrizzleDb` | type | The db handle shape the module and store expect — any SQLite-dialect driver, sync or async, schema-aware (`drizzle(client, { schema: agentSchema })`) or not |
| `AgentRunRow` / `AgentThreadRow` / `AgentMessageRow` / `AgentMemoryRow` | type | `$inferSelect` row shapes for the `agentRun`/`agentThread`/`agentMessage`/`agentMemory` tables |

<Callout type="info" title="referencedMediaIds needs no migration">
It reads the `attachments` JSON column `agent_message` has carried since attachments shipped, so an
existing database answers correctly the moment you upgrade — no new table, no column, no backfill.
The match runs in memory rather than in SQL (the column holds an array of objects, no dialect
indexes that), bounded to one actor's attachment-bearing messages. A soft-deleted thread still
counts as holding its references: the rows survive, so the bytes are still reachable.
</Callout>

<Callout type="info" title="agent_memory — the library owns this one, and not a skill table">
[Memory](/docs/agent/guides/memory) rows live in `agent_memory`, created by `ensureAgentSchema` like
the rest. That looks inconsistent next to skills, whose rows are always the host's, and the
difference is what a row can be related to: a skill plausibly joins your own entities, while a memory
is a key, a fact, an **opaque** scope token and an origin. `origin_thread_id` is the one column here
that is deliberately *not* a foreign key — a memory outlives the conversation it came from, and a
cascade off `agent_thread` would delete beliefs when a transcript aged out.

`DrizzleAgentStoreModule.forRoot({ db })` exports `DrizzleMemoryProvider` but never binds
`AGENT_MEMORY`: that token's presence is what turns memory on, so binding it would give the feature
to every host that installed the store.
</Callout>

<Callout type="info" title="agent_run — the reliability + approvals table">
Every turn is recorded as a run in `agentRun` (status, duration, error code/message, retry count, a
`promptHash` for correlating error-rate shifts with prompt changes). `DrizzleGovernanceQueries` reads
it for the dashboard's Reliability section and for `pendingApprovals`/`toolStats` — no separate table
or wiring needed, it's created by `ensureAgentSchema` like every other table here.
</Callout>

## Peer dependencies

`drizzle-orm` (`>=0.40.0 <1.0.0`) and `@nestjs/common` (`^10 \|\| ^11`).

## When to use it

Reach for this adapter when your app already owns a Drizzle connection (or wants one) and you'd
rather hand the agent a db handle than let an ORM own the lifecycle. Dialect support is
SQLite-family only (better-sqlite3, libsql, D1, …) — for other engines use
[`store-mikro-orm`](/docs/agent/packages/store-mikro-orm).
